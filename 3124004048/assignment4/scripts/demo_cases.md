# 功能演示脚本（Demo Cases）

用于课堂演示、录屏与回归验证。每条都给出了**输入 → 预期工具链路 → 预期表现**，
按顺序执行即可覆盖全部 23 个工具。

> 建议演示前先重置数据，保证结果可预期：
> 删除 `.data/todo.db`，或执行 `sqlite3` 清空 `tasks` 表。

---

## 用例 1 · 自然语言创建任务（口语时间解析）

**输入**
```
帮我记一下：明天下午3点前提交软件工程作业文档，这个最重要
```

**预期工具调用**：`add_task`
**预期表现**：回复中包含任务编号与「明天 15:00」的截止时间；
`due_date` 字段由中文口语「明天下午3点」正确解析，无需用户换算。

**验证方式**
```
/tasks          # 或调用 list_tasks，确认 due_date = 明天 15:00:00、priority = high
```

## 用例 2 · 一次说多件事（批量创建）

**输入**
```
加三个任务：今天18点和组员对分工；周五之前写完Agent说明文档；有空的时候买牛奶
```

**预期工具调用**：`add_tasks`（**一次调用**，而不是三次 `add_task`）
**预期表现**：一条消息内创建三条任务，「有空的时候买牛奶」被识别为无截止时间的低优先级任务。

**要点**：体现「工具选择」能力——模型需要判断"合并提交"比"逐条提交"更优。

## 用例 3 · 查询与统计（先查后答，不编造）

**输入**
```
我现在一共有多少任务没做完？有没有逾期的？
```

**预期工具调用**：`task_stats`（可能追加 `get_due_reminders` / `list_tasks`，视模型发挥）
**预期表现**：给出未完成数、逾期数、今日完成数，数字与数据库一致。

**反例对照**：如果模型不调用工具直接回答，则说明提示词约束失效——这是重点观察项。

## 用例 4 · 优先级排序（可解释）

**输入**
```
今天我先做哪个？帮我排一下
```

**预期工具调用**：`prioritize_tasks`
**预期表现**：返回带**分数与理由**的排序，例如
「#2 和组员对分工（88 分）：高优先级 +40、12 小时内到期 +40、高优且临期 +8」。

**要点**：排序不是黑盒，理由可向用户解释。

## 用例 5 · 日程编排（生成时间轴）

**输入**
```
帮我把今天的事情排进日程，我上午9点开始，下午6点收工
```

**预期工具调用**：`plan_day`
**预期表现**：输出带 `09:00-10:00` 这类起止时间的时间轴，自动跳过 12:00-13:30 午休，
任务间隔留缓冲；无法排入的任务进入 `unscheduled` 并说明原因。

**参数传递观察点**：模型应把「上午9点」「下午6点」映射到 `start_time=09:00`、`end_time=18:00`。

早上好，今天有什么安排？

## 用例 7 · 外部 API：天气与出行建议

**输入**
```
明天杭州天气怎么样？适合出门办事吗
```

**预期工具调用**：`get_weather` 或 `weather_travel_advice`
**预期表现**：给出温度区间、天气描述、降水概率与**明确的出行结论**（是否适合外出、要不要带伞）。

**要点**：真实外部 API 调用（Open-Meteo，免 Key），失败时返回可读中文错误而不是崩溃。

## 用例 8 · 清单导出到文件（"会做"的直接证据）

**输入**
```
把今天的待办清单导出成文件
```

**预期工具调用**：`export_checklist`
**预期表现**：返回**文件绝对路径**，例如
`D:\projects\software_engineering\homework3\exports\待办清单_2026-10-14.md`，
打开后是带表格的 Markdown 清单。

## 用例 9 · 多轮指代与修改（对话记忆）

连续三轮对话，**不要重复任务名**：

```
① 帮我加个任务：整理会议纪要，周三之前
② 刚才那个改到周五吧
③ 它不用设截止时间了
```

**预期工具调用**：`add_task` → `update_task` → `update_task(clear_due_date=true)`
**预期表现**：第二、三轮能通过「刚才那个」「它」正确指代第一条任务。

**要点**：这是**多轮对话记忆**的核心验证用例——没有记忆能力时模型会反问"哪个任务？"。

## 用例 11 · 安全确认（删除必须二次确认）

**输入**
```
把买牛奶那个任务删掉
```

**预期工具调用**：`delete_task(confirm=false)` → 用户确认后 `delete_task(confirm=true)`
**预期表现**：**第一次不会真的删除**，而是回问「请确认是否删除任务 #3「买牛奶」」；
用户回复「确认」后才执行。

**要点**：演示"AI 不越权"的设计取舍。

## 用例 13 · 语音下单（语音输入）

**操作**：点击输入框左侧的麦克风按钮（或按 `Ctrl+Shift+M`），说：
```
今天我先做哪个
```
说完再点一次麦克风结束录音。

**预期表现**：
- 录音时按钮变为渐变填充并出现呼吸光环，旁边显示计时；
- **松手/再点一下结束后立刻回放你刚说的话**（「录音后回放」开关默认开启），
  回放期间按钮显示「回放中…」，输入框上方提示「正在回放你刚才的录音…（同时进行识别）」；
- 回放与识别**并行**，约 2 秒后文字自动填入输入框**并自动发送**；
- 回放结束按钮回到「回放录音」，提示切换为识别元信息：
  `识别用时 xxxxms · 本地大模型 · 置信度 88% · 录音峰值 -1.5dBFS`；
- 随后进入正常的对话链路，出现工具卡片与真实答复。

**现场诊断用法**：若识别结果不对，**先听回放**——
原声清楚正常 → 是识别引擎的问题；原声发闷、很小、明显断断续续 → 是麦克风或系统输入音量的问题
（输入框上方的「录音峰值」也会直接标出来，正常说话应在 −18dBFS 以上）。
不用回放时，可关掉「录音后回放」开关，或事后点「回放录音」再听一遍。

**要点**：语音只是一种输入通道，识别文本直接进 `/api/chat`，因此多轮记忆与 23 个工具全部自动继承。

**引擎说明**：默认使用 faster-whisper（设置页显示「高精度 · 本地模型 small」）。
若把 `.env` 的 `VOICE_STT_PROVIDER` 改成 `sapi`，元信息会变为「命中指令模板」，
识别结果也会明显变差 —— 这是现场对比两个引擎的好素材。

**现场急救**：如果识别结果不对，让操作者点一下输入区上方的「回放录音」，
亲耳听一遍录进去的原始音频，可以立刻区分"麦克风没录好"和"识别错了"。

## 用例 14 · 语音指令参考（提升识别率的关键）

**操作**：点击输入区上方的「语音指令参考」，展开后点任意例句。

**预期表现**：例句被填入输入框。

**要点**：这些短语同时是识别引擎的**受限语法候选**。实测同一句话，
自由听写的字面准确率约 53%，而受限指令语法达到 **100%**。
所以演示时应引导听众优先使用面板里的说法。

## 用例 15 · 朗读回复（语音输出）

**操作**：
1. 点击任意助理回复下方的**喇叭按钮** → 播放该条回复的语音；再点一次停止；
2. 打开输入区的**自动朗读**开关 → 之后每条回复完成后自动播报。

**预期表现**：播放时喇叭按钮变为渐变填充并显示跳动波形；
朗读内容是**清洗过**的纯文本（不会念出「星号星号」「竖线」等 Markdown 符号）。

**验证方式**：设置页「语音输入 / 输出」卡片可查看当前音色，并有「试听合成效果」按钮。

## 用例 16 · 无密钥降级（稳健性演示）

**操作**：把 `.env` 里的 `DEEPSEEK_API_KEY` 清空后重启服务，再重复用例 13 与 15。

**预期表现**：
- 语音输入与朗读**完全正常**（识别引擎与合成音色都是本机离线的）；
- 唯一变化是设置页里「识别纠错」显示「已跳过（未配置模型密钥，直接使用原始识别文本）」；
- 若恰好说了不在指令模板里的话，识别结果可能带错别字——这正好说明纠错层的作用。

**要点**：这是刻意设计的降级路径，保证"没有付费 API 条件"的用户也能用完整的语音功能。

## 用例 17 · 「查天气」快捷按钮（直接动作，不经大模型）

**目的**：展示快捷入口不只是"替用户打一句话"，而是真的会执行动作。

**操作**：在对话框下方点「查天气」（不需要先设置任何城市）。

**预期表现**：
- 按钮短暂变为「查询中…」并置灰，右侧对话流先出现你的「查天气」气泡，再出现一张天气卡片；
- 卡片内容形如：

  ```
  🌦️ 杭州 · 今天
  小毛毛雨，22~31℃，降水概率 60%，最大风速 15.9 km/h
  有降水，记得带伞。不太适合长时间户外活动，建议把外出事务安排到天气较好的时段
  直接调用天气接口（Open-Meteo），未经过大模型 · 用的是你偏好里的默认城市
  ```

- 卡片底部会说明本次城市是怎么来的（三种之一）：

  | 情况 | 卡片末尾 |
  | --- | --- |
  | 已经说过「以后问天气默认用杭州」 | 用的是你偏好里的默认城市 |
  | 没设过偏好，且允许浏览器定位 | 按浏览器定位到当前位置（城市显示为「当前位置」） |
  | 没设过偏好，且拒绝/超时未定位 | 未设置偏好城市，暂用默认城市；说一句「以后问天气默认用杭州」就能固定 |

- 整条链路**不经过大模型**，所以没有工具卡片、耗时通常在 1~3 秒（取决于 Open-Meteo 响应）。

**对比演示（体现设计取舍）**：
先点「查天气」拿到卡片，再在对话框里输入「以后问天气默认用杭州」，
然后再点一次「查天气」——卡片城市和底部说明会同时变成杭州/偏好城市。
这既演示了跨会话的长期偏好，也说明「查天气」真的读了这个偏好，而不是写死的城市。

**现场诊断**：若卡片显示「天气没查到」，通常是网络问题（Open-Meteo 走外网），
把错误文案读出来即可；此时其余功能（任务、日程、导出）不受影响。
